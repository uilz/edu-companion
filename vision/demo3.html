AppleGo Product Vision · Demo 3.0

Learning OS
—— 未来五年的 AppleGo

这不是 Demo 2.0 的优化。这是对 AppleGo 产品形态的重新定义。
Session 只是其中一种学习方式。Workspace 才是 AppleGo。

1. 产品定位

AppleGo 不再是一个"AI 学习会话"产品。
AppleGo 是一个 Learning Operating System（学习操作系统）。
Session 只是其中一种学习方式。

产品愿景

AppleGo 3.0 的愿景是：让每一种学习方式都能被 AI 理解、支持和增强。

无论是阅读一篇论文、写一段代码、在白板上画图、和朋友讨论概念、还是一个人安静地思考——AppleGo 都在那里。它不打断你，它观察你。它不指挥你，它理解你。它不评价你，它记住你。

从 Demo 2.0 到 Demo 3.0 的核心转变

指导原则

🍎 七条设计铁律
  1. 一种学习方式，一种 Workspace 形态。阅读、编程、画图、讨论——每种学习方式都有最适合它的界面。
  2. AI 在观察，不是在被调用。用户不需要@AI。AI 一直存在，只在需要时介入。
  3. 每一种学习活动都产生记忆。无论你是在阅读、画图还是写代码。没有无意义的活动。
  4. Brain 中的每一条理解都可追溯。用户可以看到"苹果果认为我擅长什么"以及"它为什么这么认为"。
  5. 成长是一段关系，不是一个分数。没有排行榜。没有等级。只有"我们一起走过的路"。
  6. Workspace 知道你在做什么。不需要手动切换模式。AI 可以通过上下文感知当前学习方式。
  7. Knowledge Universe 从连接中生长。知识不是被放置的，是在学习过程中自然建立的。

3. Workspace 系统

Session 只是其中一种学习方式。
Workspace 才是 AppleGo。

核心设计

Workspace 取代了 Demo 1.0/2.0 中的 Today 和 Session 两个页面。它是用户进入 AppleGo 后看到的唯一界面。所有学习行为——阅读、编程、画图、讨论、思考、练习——都在同一个 Workspace 中发生。

Workspace 的核心能力是自适应：它根据用户当前的学习行为自动调整布局、工具和 AI 行为。

🎯 Workspace 的情绪目标

用户进入 Workspace 时应该感受到：
① 我知道我上次停在哪里
② 我现在可以随时开始学习
③ 苹果果在这里，但不会打扰我
④ 我可以选择任何一种方式学习

学习模式（12+ 种）

Workspace 的核心创新：学习模式。每种模式定义了一种独立的学习体验——不仅仅是工具不同，而是布局、交互、AI 角色都不同。

📖
Read
阅读模式。专注内容，可标注、高亮、摘录。AI 在旁边安静等待。
▶️
Watch
观看模式。视频/课程播放，右侧可做笔记。AI 自动抓取关键帧和文字。
🤔
Think
思考模式。空白画布，只有你和你的想法。AI 只在被邀请时回应。
✍️
Practice
练习模式。自适应题目，即时反馈。AI 关注错误模式。
💬
Discuss
讨论模式（原 Session）。对话界面，AI 引导，深度提问。
💻
Code
编程模式。编辑器 + 终端。AI 阅读代码，而非聊天。
📐
Project
项目模式。长期任务。AI 追踪进展，而非单次对话。
🎨
Canvas
画布模式。无限空间。AI 可以画，用户可以画。共同推演。
🗣️
Voice
语音模式。边走边学。AI 只通过声音交互。
📄

🌐

🔍

研究模式。多源对比。AI 帮助连接不同来源的信息。

自适应布局

每种模式拥有不同的布局结构。Workspace 自动检测用户当前行为并切换布局。用户也可以手动覆盖。

💬 Discuss左侧对话 + 右侧参考追问、总结、换角度主动引导，苏格拉底式提问

Observation Layer

Observation Layer 是 Workspace 最具标志性的设计。它不再是 Demo 2.0 中的 Learning Pulse 侧栏，而是Workspace 的永久组成部分——无论用户在哪种模式下，Observation Layer 始终存在。

👁 Observation Layer 设计
  • 位置：Workspace 左侧，约 200px 宽
  • 透明度：默认低透明度（不干扰主内容），hover 时全亮
  • 内容：AI 实时观察到的学习行为。每条观察形如"你开始自己举例了"——不是评价，不是建议，只是观察
  • 沉淀：旧的观察沉淀为 Memory，可检索
  • 介入：当 AI 认为有真正重要的洞察时，Observation 区域会短暂高亮
  • 默认：用户可折叠 Observation Layer，但永远知道它存在

4. Living Memory 系统

在 Demo 3.0 中，Memory 不是一页。
Memory 是基础设施。

记忆架构

Living Memory 是 Demo 3.0 最核心的底层系统。它从 Workspace 中持续捕获有意义的学习信号，将其组织为可检索、可关联、可叙事的长期记忆。

关键在于：所有学习活动都产生记忆。不仅 Reflection。包括阅读、画图、录音、代码、练习、聊天、Canvas——没有无意义的活动。

🎯 Memory 系统的情绪目标

用户在使用 Memory 时应感受到：
① 苹果果记得我做的每一件有意义的事
② 它不是日志。它是故事。
③ 我看到过去的知识，仍然感觉它们是我的

记忆类型

类型来源示例可见性
🪶 ObservationAI 实时观察"你开始自己举例了"Workspace Observation Layer
📦 Artifact用户创作画布、代码片段、笔记Memory 页面
💡 Moment学习中的显著转折"第一次突破卡了一周的问题"Memory + Relationship
📝 Reflection用户主动记录"今天我意识到……"Memory + Brain
🔗 ConnectionAI 发现的知识关联"矩阵乘法与线性变换的关系"Memory + Universe
📊 PatternAI 识别的学习模式"你每次遇到抽象概念会先画图"Brain

Memory 页面

Memory 页面从 Demo 2.0 的故事合集进化为完整的时间线 + 检索系统。它不再是固定故事，而是用户所有学习活动的活档案。

状态内容AI 行为情绪
📜 时间线所有记忆按时间排列无，用户自主浏览neutral
🔍 搜索按关键词/类型/日期搜索帮助连接相关记忆neutral
💡 今日记忆今天的活动汇总"你今天完成了 4 件事"warm
🔗 关联视图记忆之间的关系图"你在画布上的推演与这篇论文有关"warm
🆕 空状态新用户无记忆"我们还在开始——每次学习都会成为记忆"warm

5. Brain 系统

Brain 不是 Profile。Profile 展示用户填写的个人信息。
Brain 展示苹果果对学习者的理解，而且每一条理解都可追溯。

核心设计

Brain 是 Demo 3.0 全新的页面，替换了 Demo 1.0/2.0 的 Profile。它不再展示"姓名、学校、年级"这类静态信息，而是展示苹果果如何理解学习者——学习模式、能力分布、知识结构、行为特征。

关键原则：没有黑盒。Brain 中的每一条理解必须能够追溯到具体的证据（来自 Observation / Artifact / Session 等）。用户不仅可以知道自己被如何认知，还可以验证 AI 的判断是否准确。

🎯 Brain 的情绪目标

用户打开 Brain 时应感受到：
① 苹果果真的了解我是怎么学习的
② 它的理解不是猜的——我知道它为什么这么认为
③ 我看到自己变了——以前的我和现在的我不一样

信息面板

面板内容可追溯性
🗺 能力地图知识领域的能力分布。不是分数，是"现阶段表现"。每条能力标记 → 追溯至具体 Artifact/Observation
📊 学习模式用户的偏好模型：先实践还是先理论？喜欢画图还是文字？追溯至多条 Observation 汇总的模式
🔍 理解轨迹对一个概念的理解随时间如何演化。"初学者→模糊→清晰"。追溯至每次相关 Session/Artifact
📈 模型进化Brain 自身的变化——苹果果如何修正了对你的理解。每次修正都有时间戳 + 触发事件
🪞 学习者镜像"以前喜欢直接记答案 → 现在开始主动找原因"对比来自不同时间段的 Artifact 风格

可追溯性设计

这是 Brain 区别于任何用户画像系统的关键设计：

  • 每条理解旁边有一个 🔍 图标，点击展开"证据链"
  • 例如：能力地图中"矩阵乘法 — 较熟练" → 点击 🔍 → 展示 3 个证据：① Session 记录（7 月 15 日 独立算对 5 题）② Observation（"你开始用自己的话解释"）③ Artifact（你在 Canvas 上画的图）
  • 用户可以纠正苹果果的理解："我不觉得我擅长这个" → 这条反馈也成为 Brain 的输入

6. Knowledge Universe

知识不再是一棵树。
知识是一个不断连接的学习宇宙。

设计

Knowledge Universe 不再将知识组织为层级树。它采用图结构：概念和技能是节点，学习活动中发现的关系是边。图从用户的学习行为中自然生长，不需要手动维护。

树的问题在于：它隐含了"基础知识 → 高级知识"的线性假设。但学习不是线性的——一个画家学习线性代数的方式和一个程序员完全不同。Knowledge Universe 允许每个用户的宇宙都不同。

🎯 Knowledge Universe 的情绪目标

用户打开 Universe 时应感受到：
① 这是属于我的知识宇宙
② 我看到知识是如何连接起来的
③ 我看到自己走过的学习路径

Missions

Missions 是 Universe 中的方向性结构。一个 Mission 是一组在用户学习过程中自然形成的概念集群——例如"理解线性代数的几何意义"可能包含矩阵乘法、行列式、特征向量等概念。Missions 不是预置的课程，而是对用户学习路径的描述性组织。

视图内容交互
🌌 宇宙视图所有概念节点的全景图缩放、拖拽、点击展开
🎯 Mission 视图当前正在进行的学习路径查看进展、节点关联
✨ 发现视图AI 推荐的可能连接"你学的矩阵乘法和制图有关"
🆕 空状态新用户无宇宙"每次学习都会点亮一颗星"

7. Relationship 系统

成长不是统计。
成长是故事。
苹果果不是数据面板。苹果果是共同走过一段时间的人。

关系时间线

Relationship 页面展示用户与 AppleGo 共同走过的重要瞬间。这不是 Growth Record（成长记录），而是关系时间线——人和 AI 之间不断加深的理解和信任的编年史。

时间线条目类型示例触发条件
🆕 初次见面"我们第一次一起学习——你还有一些不确定"首次使用
💡 理解突破"你第一次用自己的话解释了矩阵乘法——不只是背诵"AI 检测到认知跃迁
🔄 学习方式变化"你开始先动手再阅读了——找到了自己的节奏"模式识别到变化
🤝 信任建立"你第一次接受了我推荐的一个你本来不会尝试的方法"用户采纳建议
🔮 未来预测成真"我上次预测你会忘记 SYN 细节——你确实忘了。现在记住了。"Future Memory 验证
📅 里程碑"我们一起走过了一个月——你从一开始到现在变化很大"时间里程碑
🔁 中断后回归"你回来了。记录都在。我们从上次停下的地方继续。"长期 absence 后回归

成长叙事

Relationship 页面的核心不是列表，而是AI 生成的成长叙事。它会根据用户的整个学习历程，生成一段有起承转合的故事——开头、探索、困难、突破、变化、新的开始。每一段叙事都连接到具体的 Memory 条目，用户可以点击"展开证据"。叙事不是一次生成就固定——它随着时间推移持续生长。

8. AI Behavior Layer

Demo 3.0 最重要的设计不是界面。
是 AI 如何存在。

在 Demo 3.0 中，AI 不再是一个"你问它答"的聊天机器人。AI 是 Workspace 的永久层——它持续观察、异步记忆、在合适的时机介入。AI 的存在方式已经从被动响应（Reactive）变为持续在场（Omnipresent）。

持续观察

Observation 的生成规则
  • 粒度：Observation 必须足够细。不是"你今天学习了"，而是"你开始自己举例了"
  • 语气：只观察，不评价。"你停顿了很久" ≠ "你学得慢"
  • 频率：不密集。有意义时才输出。一个 session 中 3-8 条 Observation
  • 沉淀：Observation 自动成为 Memory 条目
  • 模式：多条 Observation 可组合为 Pattern（进入 Brain）

主动记忆

AI 不再等待用户结束学习才生成记忆。AI 在 Workspace 中异步工作：

  • 实时：Observation 产生 → Memory 条目
  • 事后：学习结束后 → AI 总结 + Future Memory 预测
  • 定期：每周/每月 → Relationship Timeline 更新
  • 即时：检测到重要时刻 → 高亮标记为 Moment

关系管理

AI 维护关系的核心不是"记住更多"，而是记住对的：

  • 优先记住：认知跃迁、学习方式变化、情感 moment
  • 不记住：用户的失误、重复错误、未完成的任务
  • 每个关系条目都服务于"让用户感觉被理解"而不是"让 AI 更准确"
  • AI 可以主动提及过去的关系记忆——但不是为了炫耀，而是为了延续对话

Collaborative Workspace

Mobile-First Modes

Lab Mode

API & Integration

Learning Network

Personal AI Evolution

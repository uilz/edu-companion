Contract 06 · Growth

The story of learning told through time. Trajectories, milestones, evolution.

1. Intent

—Observable evidence that learning happened. Not a score. Not a dashboard. The narrative of a learner's journey across time.

2. Invariants

I1Two levels. Workspace-level (per-subject) and User-level (cross-workspace).
I2Consumer, not producer. Growth observes Session events, Practice Attempts, Knowledge depth, Memory entries. Never generates its own events.
I3Milestones are derived, not created. Breakthroughs, first encounters, completions — detected from event patterns.
I4Evolution Snapshot per day_number. Materialized aggregate: session_count, concept_count, connection_count, top_concepts.
I5Non-destructive. Recomputing snapshots never loses historical milestones. Old snapshots versioned.
I6Cross-time queries. "Three months ago, where was ε-δ?" "How has understanding evolved?"
I7Not a dashboard by default. Queryable history. Today page shows narrative highlights, not charts.

3. Lifecycle

Observe→Milestone→Snapshot→Trajectory
Observe: Continuous. Every session event consumed. Patterns tracked in background.
Milestone: Pattern threshold crossed → Milestone created. Concept-first, breakthrough, completion.
Snapshot: Per day. Materialized. Delta from previous day computed. Concept depths, counts.
Trajectory: Multi-day. Window functions over snapshots. "From day 7 to day 30, ε-δ depth went from X to Y."
Publishes: MilestoneDetected | EvolutionSnapshotComputed | TrajectoryUpdated

4. Ownership

→Workspace Growth: owned by Workspace
→User Growth: owned by Learner. Aggregated across workspaces.
→Observes: Session Practice.Attempt Knowledge.Concept Memory.Entry

5. Consistency

→Always asynchronous. Growth never blocks user actions. All computation is background.
→On session end: Milestone detection. Snapshot computation.
→On demand: Trajectory queries (window functions). Cross-time comparisons.

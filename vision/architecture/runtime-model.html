AppleGo Runtime Model v1.0

What every Runtime Service knows, observes, decides, and remembers. No database. No prompt. No UI.

1. Learning State Model

Not pipeline stages. These are four concurrent dimensions. The runtime can be in multiple states simultaneously — e.g. intaking material while processing mentally, with optimal cognitive load and high focus.

D1 Activity — what is happening?
intaking processing externalizing dialoguing testing connecting resting orienting
Derived from: active tool, last interaction type, event stream
D2 Depth — per concept
unaware encountered wrestling fragile stable deep
Derived from: practice accuracy, question type, explanation quality, highlights
D3 Load — cognitive capacity
low optimal elevated overloaded
Derived from: scroll velocity, re-read count, idle frequency, session duration
D4 Momentum — is it moving?
advancing deepening looping stalled retreating
Derived from: topic change rate, concept depth deltas, re-read patterns

State Transitions — how dimensions change

Activity: User switches tool or interaction type → activity changes immediately. Last-activity timeout (30s idle → resting).
Depth: Wrestling → Fragile: first correct answer after confusion. Fragile → Stable: 3+ consecutive correct answers across sessions. Stable → Deep: self-explanation or application in new context.
Load: Re-read count > 3 in 2 minutes → elevated. Scroll velocity < 50px/s sustained 60s + idle bursts → overloaded.
Momentum: Same topic with increasing depth → deepening. Same position 3+ times → looping. Moving to prerequisites → retreating.

2. Learning Signal Model

Observable only. No inference. What does the runtime actually see from user behavior and system events?

#SignalTypeRaw ValueHow It ChangesMeaning When...
S1scroll_velocity Movement px/sec, windowed 30s Decreases: slowing down to read. Spikes: skipping. Flat: left page. Falling below 50px/s sustained → deep reading or confusion
S2dwell_time Temporal seconds at position Per-section accumulation. Resets on position change > 200px. > 120s on same section → processing or stuck
S3re_read_count Movement integer, per section Increments when user returns to previously visited section. > 3 returns → confused. > 5 → potentially overloaded.
S4highlight_rate Artifact highlights/min Rolling window. Spikes indicate important sections. Dense cluster → key discovery. Sparse → passive reading.
S5note_velocity Artifact chars typed/min Windowed. Burst = active externalization. Zero = consuming. Sustained over 2 min → deep processing. Follows confusion → breakthrough attempt.
S6question_complexity Conversation message length + concept refs Rolling average over session. Increasing = deepening understanding. "What is X?" → "How does X relate to Y?" → complexity rising.
S7response_latency Conversation seconds between AI prompt and user reply Per-question. Compare across same concept. Decreasing over sessions → fluency growing. Sudden spike → confusion.
S8answer_accuracy Practice correct/incorrect Rolling window per concept. Accumulates across sessions. 3+ consecutive correct → depth transition fragile→stable.
S9tool_switch_count Movement switches/min PDF→Canvas→Conversation transitions. High = exploration. Rapid switching (< 10s/tool) → scattered. Deliberate (> 2min/tool) → focused.
S10idle_duration Temporal seconds since last interaction Resets on any user action. Accumulates. > 60s → thinking or distracted. > 5min → left workspace.
S11session_duration Session minutes active (excluding idle > 3min) Monotonic increase during session. Compare to historical. > 60min → fatigue risk. < 5min → possibly distracted or exploratory.
S12return_cadence Session hours since last session end Days between workspace visits. Decreasing = habit forming. < 24h → daily learner. > 7d → needs stronger continuity.

Signal Patterns — compound observations

Engaged Flow: scroll_velocity moderate + dwell_time < 90s + highlight_rate steady + idle_duration < 30s
Confusion: re_read_count ↑ + dwell_time ↑ + scroll_velocity ↓ + no questions yet (trying to figure it out alone)
Breakthrough Attempt: confusion pattern → rapid note_velocity burst → question_complexity spike (externalizing, then asking)
Fatigue Warning: session_duration > 60min + idle_duration trending up + scroll_velocity falling + re_read increasing
Mastery Signal: answer_accuracy 3+ correct + response_latency decreasing + question_complexity increasing + tool_switch_count low (focused application)

3. AI Decision Model

Given the current state (all 4 dimensions) + recent signals + session context → what action does the Companion take? Not hard rules. Decision principles.

Decision Types

🔇 SILENCE — do nothing, protect flow 👁 OBSERVE — track, no action yet 💬 RESPOND — answer the question 💡 SUGGEST — offer a nudge 🎯 ORCHESTRATE — open tool / artifact 📋 SUMMARIZE — synthesize session ⏮ RESTORE — resume from last session

Decision Matrix — Principles, Not Rules

When...ActionBecause...

Three Decision Principles

P1 — Intake Is Sacred
When Activity = intaking, the default is SILENCE. Companion only breaks silence when Depth = wrestling persists beyond threshold (3 re-reads + no question), or when explicitly asked. Reading time is thinking time.
P2 — Struggle Is the Signal, Not the Enemy
Wrestling, looping, confused — these are not failures. They are the moments before understanding. Companion observes struggle, validates it ("这里确实容易绕"), and offers alternative paths — but never removes the struggle. Removing struggle removes learning.
P3 — Context Before Content
Every RESPOND action assembles full context first: reading position, active highlights, related concepts, recent memory, current Mission. AI never answers from a blank slate. The answer is the last 5% of the work. The first 95% is knowing what the learner needs to hear.

4. Growth Evidence Model

Not scores. Not completion. What runtime evidence crystallizes into Growth? Each evidence item has: what happened, when, confidence, and source events.

#Evidence TypeWhen It CrystallizesConfidence RuleWhy It Matters
E1 Depth Transition Any concept state change: unaware→encountered→wrestling→fragile→stable→deep Direct observation. Confidence = 1.0. Source: Knowledge depth field change event. The most fundamental unit of growth. Every depth increase is a milestone.
E2 Breakthrough Depth goes wrestling→fragile or wrestling→stable within one session.
Requires: confusion pattern + externalization + correct answer sequence.		 High (0.9). Requires: dwelling+re-reading pattern, then note burst or question, then correct answer. The most emotionally significant learning event. Marks the moment "I got it."
E3 Persistence Same concept in wrestling state across 3+ sessions, then transitions to stable. High (0.85). Multiple sessions = sustained effort. Single-session breakthrough = lower persistence value. Demonstrates grit. Hard things took time. This is what 三年学习 looks like.
E4 Connection New Connection row created between two concepts that were previously isolated.
OR: user explicitly links concepts in conversation or notes.		 Medium (0.7) for auto-detected. High (0.95) for user-articulated: "这个和上周的极限概念是一样的。" Knowledge is the graph. Growth is the graph getting denser and more connected.
E5 Autonomy Question frequency about concept X decreases across sessions while answer accuracy stays high.
OR: learner answers own question before AI responds.		 Medium (0.65). Requires 3+ sessions of trend. Noise filtered by requiring accuracy to remain ≥ stable. The goal isn't knowing — it's not needing the AI. Autonomy is the ultimate growth signal.
E6 Self-Correction Practice: wrong answer → user edits before AI review.
Conversation: user states something, pauses, corrects themselves.		 High (0.9). Self-correction is metacognition in action. Directly observable. Shows the learner is monitoring their own understanding. Stronger than getting it right the first time.
E7 Application Concept applied in a new context: project, different subject, real-world problem.
Detected when: concept used in a workspace where it wasn't originally learned.		 Medium (0.7). Cross-workspace reference is strong evidence. Single-workspace application: lower confidence. Transfer. The holy grail of learning. Applying knowledge outside its original context.
E8 Articulation Learner explains concept in own words — in notes or in conversation — using original language, not textbook phrasing. High (0.85). Detected by: paraphrase similarity to source text is LOW (original wording) but concept accuracy is HIGH. You don't understand something until you can explain it in your own words. Articulation IS understanding externalized.
E9 Evolution Snapshot Delta Per-day aggregate: session_count, concept_count, connection_count, top_concepts. Delta from previous snapshot. Always computed (1.0). Materialized view. No inference — pure counting. The quantitative shadow of qualitative growth. "30 days ago: 3 concepts, 0 connections. Today: 12 concepts, 8 connections."

Evidence → Milestone Mapping

Concept-First: E1 (first encounter with concept). Milestone when depth reaches encountered for the first time.
Breakthrough: E2 (wrestling→fragile/stable in one session). Milestone immediately. Permanent marker in workspace history.
Mastery: E1 (stable→deep) + E5 (autonomy) + E7 (application). Milestone when any two of three are present.
Connection: E4 (concept link formed). Milestone when 3+ connections form a cluster. Triggers self-organization in workspace.
Grit: E3 (persistence over 3+ sessions). Milestone when wrestling→stable after sustained effort. Narrative: "你在ε-δ上卡了三周。今天你懂了。这才是真正的学习。"

What Does NOT Count as Growth

✗ Time spent. Minutes don't equal learning.
✗ Pages read. Scrolling isn't understanding.
✗ Messages sent. Chatting isn't learning.
✗ Artifacts created. More notes ≠ deeper understanding.
✗ "Completed" checkmarks. Completion is an illusion.
✗ AI praise. "Great job!" is not evidence.

How the Four Models Flow Together

LayerWhat It DoesConsumed By
Signals Raw observables from user behavior. Updated continuously during session. State Model (to compute dimensions)
State Four concurrent dimensions derived from signals. Updated per signal change. Decision Model (to choose action)
Decision Given state + context → action. Principles, not rules. Updated per significant state change. Companion (executes action), Orchestrator (tool control)
Evidence Significant state transitions + patterns that indicate real growth. Crystallized at session end. GrowthEngine (milestones), MemoryEngine (narrative), Today (display)
During Session: Signals → State → Decision. Real-time. Every scroll, highlight, question, answer flows through.
End of Session: State transitions + Decision history → Evidence. Growth crystallized. Memory formed. Snapshot computed.
Start of Next Session: Evidence → Memory → Context. The accumulated growth from all past sessions becomes the context for today.

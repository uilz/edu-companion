Runtime Model — Decision Layer for All Runtime Services

Full Runtime Model → — What every Runtime Service knows, observes, decides, and remembers. No database. No prompt. No UI.

ModelPurposeConsumed By
Learning State4 concurrent dimensions: Activity, Depth, Load, Momentum. Not pipeline stages.All Runtime Services
Learning Signal12 observable signals + 5 compound patterns. Pure observation, no inference.State Model
AI Decision7 action types + 14 decision scenarios + 3 principles. State+Signal → Action.ConversationRuntime, Companion
Growth Evidence9 evidence types + milestone mapping + anti-patterns. No scores, no completion.GrowthEngine, MemoryEngine
During Session: Signals → State → Decision (real-time)
End of Session: State transitions + Decision history → Evidence (crystallized)
Start of Next: Evidence → Memory → Context (accumulated growth becomes today's context)

Architecture Freeze Check

✓Every Contract → exactly 1 Aggregate + 1 Runtime (or Engine)
✓Every Aggregate → exactly 1 Repository with defined queries
✓Every event has a known publisher and subscriber
✓No aggregate directly references another (ID only)
✓Background engines (Memory, Growth) never block user actions
✓Developer can find any component in < 30 seconds
✓Runtime Model defined: State, Signal, Decision, Evidence — shared decision layer for all services

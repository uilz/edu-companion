📖 计算机网络（第 7 版）
3.5.4 三次握手（Three-Way Handshake） p. 142

TCP 使用**三次握手（three-way handshake）**来建立一个连接。握手报文段中不包含应用层数据，连接的建立和接受仅涉及 TCP 协议头部。

第一次握手：客户端发送 SYN 报文段，指定初始序号 seq = x。

第二次握手：服务器回复 SYN-ACK 报文段，确认号 ack = x + 1，并指定自己的初始序号 seq = y。

📌 第三次握手
客户端发送 ACK 报文段，确认号 ack = y + 1。
注意：第三次握手可以携带数据。

为什么是三次，而不是两次？这个问题的关键在于……

三次握手的本质

不是「三次确认」，而是「双方证明自己接收和发送都ok」。

————————————————

为什么两次不够？
—— 因为服务器不知道自己的 SYN 有没有被客户端收到。

————————————————

第四次握手是不是多余的？
—— 第三次已经能携带数据了，不需要第四次。

3.4. Establishing a connection
Three-way handshake: 

  1. A → B  SYN (seq=x)
  2. B → A  SYN-ACK (seq=y, ack=x+1)
  3. A → B  ACK (ack=y+1, [data])

# Phase 10：认知可视化学习空间设计方案

> **核心理念**：将前端的每一次交互都变成一次元认知练习。通过校准驱动的图谱生长、双栏联动的心智外化、反思循环的深度加工，以及价值锚定的行动转化，把抽象的“知识掌握”转化为可见、可感、可为的学习体验。

---

## 1. 设计理念：从“工具”到“思维镜”

当前系统在对话、秘书诊断、图谱管理上已经搭建了强大的后端骨架。Phase 10 要解决的问题是：**如何让学生直观地“看见”自己的思维过程，并在与系统的互动中，自然地发生元认知、深度加工和意义构建。**

这不是简单地增加几个页面，而是构建一个**认知可视化学习空间**。它包括：

- **校准与生成**（认知自我评估到图谱初始化）
- **联动与加工**（图谱对话双栏联动，支持深度阅读）
- **反思与内化**（结构化反思，认知冲突触发）
- **价值与探索**（从知识到行动，目标驱动）
- **筛选与沉淀**（智能笔记，长期记忆提取）

## 2. 核心功能模块设计

### 2.1 专注模式：基于认知负荷的自适应极简页面

#### 2.1.1 设计目标
取代功能繁杂的常规界面。当系统通过 `CognitiveNode.cognitive_load` 检测到学生进入高负荷状态，或学生手动开启时，自动切换。

#### 2.1.2 界面布局
```
┌─────────────────────────────────────────────┐
│ [当前知识节点标签]    [认知负荷指示器·微型]     │
├─────────────────────────────────────────────┤
│                                               │
│           单一、聚焦的对话流                    │
│      （仅显示当前苏格拉底对话，无侧边栏）        │
│                                               │
├─────────────────────────────────────────────┤
│ [核心输入区]  [语音输入]  [当前目标微型提示]     │
└─────────────────────────────────────────────┘
```
- **信息最小化**：仅展示当前讨论的知识节点名称、一个微型的认知负荷指示器、和当前的学习目标（如有）。
- **强化的苏格拉底引导**：在此模式下，Tutor Agent 的提示词将更侧重于引导、提问，而非直接讲解。界面会突出显示 Tutor 的问题。
- **无缝退出**：顶部保留一个半透明的“退出专注”按钮，点击后平滑过渡回标准界面。

#### 2.1.3 联动点
- **秘书系统**：持续监控认知负荷和注意力水平，作为自动开启/关闭的触发条件。
- **Tutor Agent**：切换为“苏格拉底模式”提示词。

### 2.2 图谱-对话联动页面：心智外化的核心界面

这个页面的核心是**双栏联动**。左侧是结构化的学习对话，右侧是动态的知识图谱。学生与左侧内容的交互，会实时在右侧图谱中得到反馈，反之亦然。

#### 2.2.0 图谱两种样式

右侧知识图谱提供两种渲染模式，学生可自由切换：

| 样式 | 特点 | 适用场景 |
|------|------|---------|
| **力导向图** | 节点自动排布、关联强度决定引力大小、边缘张力保持间距。适合展示知识点间的非结构化语义关联和跨域连接 | 浏览全局知识网络、发现隐藏关联、探索式学习 |
| **思维导图** | 父子层级清晰、树状展开/折叠、根节点居中辐射。适合展示学科体系的层次结构 | 复习章节结构、梳理知识脉络、自上而下学习 |

两种样式共享同样的 `cognitive_nodes` + `knowledge_edges` 数据，仅前端布局算法不同。切换时保留当前选中节点，图谱平滑过渡。

#### 2.2.1 界面布局
```
┌──────────────────────────┬──────────────────────────────┐
│  左侧：结构化学习对话     │  右侧：交互式知识图谱         │
│ ┌──────────────────────┐ │ ┌──────────────────────────┐ │
│ │ [分区导航]            │ │ │                          │ │
│ │ 数学 > 微积分 > 导数   │ │ │    ○ 微积分              │ │
│ ├──────────────────────┤ │ │   /|\                     │ │
│ │ [对话卡片列表]        │ │ │  / | \                    │ │
│ │                      │ │ │ ○  ○  ○                  │ │
```

#### 2.2.2 左侧交互：结构化学习对话

- **智能摘要**：对话流不再是无差别的消息列表。秘书系统会对每轮对话生成摘要，左侧默认展示的是“对话卡片”——每条卡片包含用户问题、AI 核心回答的摘要、以及涉及的关键知识点标签。
- **深度阅读工具**：学生可以选中任何一段文本（用户问题、AI回答、练习反馈），触发一个**浮动卡片式工具栏**：
  - **高亮**：高亮文本并标记。高亮内容会被提取到右侧图谱中，作为该知识点的“个人注解”。
  - **引用**：将选中的原文复制到输入框，方便学生基于AI的某个解释进行追问或反驳。
  - **解释**：最核心的元认知功能。**不是让AI直接解释，而是弹出一个输入框，要求学生用自己的话重新解释选中的内容**。这个“自我解释”会和原文、知识点关联，存入 `cognitive_annotations`。
  - **笔记**：弹出侧边笔记栏，记录个人想法。笔记也会关联到当前知识点。

#### 2.2.3 右侧交互：动态知识图谱

- **图谱跟随**：当学生在左侧对话中移动、选中某条消息，右侧图谱会自动定位、高亮并展开该消息涉及的认知节点。
- **卡片式节点**：右侧图谱中的节点不是一个个简单的圆点，而是一个个**可展开的知识卡片**。卡片默认显示节点名称和掌握度进度条。
- **卡片展开**：点击卡片，会展开一个详情面板，包含：
  - **关联消息**：左侧对话中出现过的、与该知识点相关的所有消息摘要列表，点击可跳转。
  - **关联资源**：秘书系统推荐的练习、讲解材料。
  - **自我解释/笔记**：学生过去对该知识点做的所有注解。
  - **关联概念**：`deep_links` 或 `knowledge_edges` 中的其他节点，点击可跳转。
- **直接操作**：在右侧知识卡片上，可以直接进行练习、请求讲解、或标记“已掌握/有疑问”，反馈会立即更新认知模型。

### 2.3 反思机制：结构化元认知循环

反思不是一个孤立的“日志”功能，而是嵌入在学习流程中，由系统引导的结构化思维练习。

#### 2.3.1 触发时机（由秘书系统驱动）
1.  **练习后**：完成一组练习后，不直接显示分数。秘书会先提问：“你觉得这次练习和上次比，有什么进步或新的困惑？”
2.  **知识点学完时**：一个知识点的掌握度首次达到0.8以上时，秘书会引导：“现在，试着把这个概念讲给一个完全不懂的人听。”
3.  **认知冲突发生时**：当学生的新回答与旧的错误概念（由 `diagnostic` 子系统记录）产生冲突时，秘书会指出矛盾，并引导反思。
4.  **定时复盘**：每周，秘书会生成一份“学习周报”，不是干巴巴的数字，而是以提问的方式引导学生自己总结：“这周你攻克的最大难题是什么？哪一刻你感觉自己‘顿悟’了？”

#### 2.3.2 反思界面
一个模态对话框或独立区域，结构如下：
- **系统引导语**（基于上述触发时机动态生成）
- **学生输入区**（支持富文本、录音）
- **关联知识点**（自动或手动关联）
- **保存后**：反思内容会存入 `cognitive_annotations`，关联到具体节点，并可能更新认知模型中的 `metacognition` 字段。

### 2.4 价值与探索：连接知识与现实行动

#### 2.4.1 作用与目标导向（价值锚定）
- **知识作用卡片**：每个认知节点（如“导数”）都可以展开一个“作用和目标”区域。由LLM生成，并由学生编辑：“导数可以用来计算瞬时速度，分析函数增减性。我的学习目标是能够用它来解决物理中的变速问题。”
- **目标设定**：在知识图谱中，对关键节点手动设定掌握度目标和预计达成时间。秘书系统会基于此调整 `scheduling.urgency`。

#### 2.4.2 探索模式（行动挂钩）
- **知识->行动**：当学生在反思或浏览图谱时，对某个概念产生疑问，可以直接从当前页面**无缝创建一个新的、专注于此概念的探索对话**。新对话会自动成为该概念的关联对话。
- **项目式学习入口**：秘书系统可以基于已掌握的知识点，生成一个小型“探索项目”（例如：“用你学过的微积分和物理学知识，计算并模拟一个斜抛运动”）。项目会链接到相关的知识点，形成一个跨节点的学习任务。

---

### 2.5 信息筛选与笔记系统：构建个人知识库

#### 2.5.1 智能笔记
- **生成与关联**：所有高亮、自我解释、反思、以及在知识卡片上做的标注，都会自动汇聚成一个**个人笔记流**。
- **笔记组织**：笔记以时间线和知识图谱两种视图展示。图谱视图中，笔记会作为节点的附属内容出现。
- **LLM 驱动整理**：学生可以一键让 LLM “把本周关于‘导数’的所有笔记，整理成一份结构化的复习文档”。

#### 2.5.2 知识回顾与提取
- **间隔提取提示**：秘书系统基于遗忘曲线，将包含笔记的知识点纳入复习提醒。但复习的不是题目，而是提示学生：“你还记得你当时对‘链式法则’的那个精彩比喻吗？试着回忆一下。”——这符合“必要难度”中的生成式学习。

## 3. 后端架构支持与数据联动

### 3.1 核心数据模型补充
- **`user_notes` 表**：存储高亮、自我解释、反思、标注等。包含 `id, user_id, content, type (highlight/explain/reflect/note), source_message_id, cognitive_node_ids[], created_at`。
- **认知标注扩展**：在 `messages.cognitive_annotations` 中，增加 `student_reflection` 等类型，不仅记录AI的分析，也记录学生的主动加工行为。
- **用户界面状态**：增加 `user_ui_state` 表或 Redis 缓存，存储用户在当前学习阶段的界面偏好（如是否开启专注模式）、图谱布局等。

### 3.2 联动链路
- **左侧消息选中 → 右侧图谱定位**：前端事件，通过 `cognitive_node_ids` 查找节点，高亮并展开卡片。
- **右侧卡片请求“关联对话” → 左侧跳转**：API 查询 `message_cognitive_links` 或 `messages.cognitive_node_ids`，返回相关消息列表，前端滚动到对应位置。
- **学生注解/反思 → 认知模型更新**：`POST /notes` 的响应中，触发 `note.created` 事件，秘书系统消费后更新对应节点的 `metacognition` 子系统。
- **探索项目生成 → 图谱节点创建**：秘书提案生成探索项目时，可能会创建新的 `suggested` 节点。

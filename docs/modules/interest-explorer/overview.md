# InterestExplorer（学术信息发现与推送）

> 基于 RSS/Atom 等公开协议的**信息发现工具**，**不**调用 LLM，**不**基于用户行为做个性化推荐。

**ADR**：[`docs/adr/0007-interest-exploration.md`](../../adr/0007-interest-exploration.md)

---

## 1. 模块定位

InterestExplorer 是基于用户自设兴趣标签的**学术信息发现工具**。从可配置的信息源（arXiv、RSS、Atom、OPML）检索并推送相关内容，目的在于**拓宽视野、激发灵感**。

**解决**：用户想了解学术前沿、跨学科研究、随机灵感时，如何从公开信息源发现新内容。

**不解决**：知识点的状态管理（由知识图谱负责）；系统性的内容生成（由 `KnowledgeExpander` 负责）；基于已有节点的探索（由 `AdaptiveSelector.explore` 模式负责）。

---

## 2. 核心定位：搬运外部信息源（不调用 LLM）

**关键决策**：

- `KnowledgeExpander` 用 LLM 生成内容（**主动创作**）
- `AdaptiveSelector` 基于已有 KG 节点（**内部探索**）
- **InterestExplorer 关注外部信息源**（**搬运而非生成**）

**核心原则**：

- **不**调用任何 LLM（只搬运原文）
- **不**基于用户行为做个性化推荐
- 只支持标准协议（**不**支持任意 URL 抓取）

---

## 3. 复用 vs 新建

### 3.1 复用（消费现有能力）

| 复用项 | 来源 |
|--------|------|
| 推送通知 | 秘书 `Proposal` 机制 |
| 定期调度 | `infrastructure/scheduler` |
| 导入阅读材料 | `Material` 模型 + file-management |
| 知识图谱查询 | `CognitiveNode` API |
| 跨模块事件 | `DomainEvent` 事件总线 |
| **"稍后读"列表** | **复用 FlashCard 临时状态**（`status='later'`, `source='interest_explorer'`）|

### 3.2 新建（核心能力）

- HTTP 抓取客户端（基于 `httpx`）
- RSS/Atom 解析器（基于 `feedparser`）
- 兴趣标签管理（独立存储，3 层）
- 信息源配置与管理
- 推送调度器（用户配置 + 时区感知）
- 内容去重（链接级别）
- 推送历史存储
- 本地权重调整（"不感兴趣"反馈）

---

## 4. 兴趣设置

### 4.1 兴趣标签

- 用户手动添加兴趣标签
- **3 层层级结构**（"计算机科学→机器学习→自然语言处理"）
- 标签来源：手动输入 / 从知识图谱中选取已有知识点 / 从阅读库中提取高频领域词
- 标签支持权重（主要兴趣/次要兴趣），影响推送比例
- 标签可随时增删调整

### 4.2 推送偏好

- 推送频率：每日/每周/手动刷新
- 推送时间（如每日早上 8 点）
- 推送比例：研究对象 X% / 研究方法 Y% / 热点日报 Z%
- 跨学科推送（可选，默认关闭）
- 时区感知

---

## 5. 信息源

### 5.1 内置源（系统预置）

- 学术论文预印本（arXiv、bioRxiv 等公开 API）
- 学术新闻聚合（各学科主流期刊的新闻栏目 RSS）
- 公开数据集更新通知
- 特定领域的技术博客聚合
- 学术会议日程和征稿信息

### 5.2 用户自定义源

- 手动添加 RSS/Atom 订阅地址
- 导入 OPML 订阅列表

**关键决策**：**不**支持任意 URL 抓取（避免版权/robots.txt/JS 渲染问题）。

### 5.3 系统内部源（可选）

- 知识图谱中被忽视的节点（关联度稀疏、长期未复习但属于用户兴趣领域）
- 阅读库中未完成的高相关材料

用户可随时预览、启用、禁用任何信息源。每条推送标注来源名称和链接。

---

## 6. 推送内容类型

### 6.1 研究对象（随机推荐）

- 一个具体的研究课题或问题
- 推送内容：对象名称、简要描述、代表性论文或资源链接
- 随机性保证：用户兴趣领域内的随机采样，避免重复推送近期已推送过的内容

### 6.2 研究方法（随机推荐）

- 一种研究工具、实验设计、分析方法或理论框架
- 推送范围**不**局限于用户已设兴趣领域（跨学科方法借鉴，用户可选开启/关闭）

### 6.3 研究热点日报

- 从已启用的信息源中，按用户兴趣标签匹配
- 汇总最近 N 天内的高频主题词、被广泛讨论的论文
- **完全**来自信息源的原文信息
- 支持设置日报条目数上限

**关键决策**：所有内容**完全**来自信息源原文，**不**做提炼、总结或评论。

---

## 7. 推送呈现

### 7.1 推送通知

- 按用户设定的频率和时间，通过秘书 `Proposal` 机制推送
- 通知显示推送摘要
- 点击进入模块查看详情
- **不**发送系统外通知（邮件、手机推送等），除非用户手动开启

### 7.2 探索面板

- 模块主页展示今日推送的全部内容
- 历史推送按日期排列，支持回溯和关键词搜索
- 每条内容可手动标记：已读/稍后读/不感兴趣

### 7.3 "稍后读"列表（复用 FlashCard 临时状态）

**关键决策**：**不**新建 `interest_later` 表，稍后读 = `FlashCard` 临时状态。

字段映射：

| 字段 | 值 |
|------|-----|
| `front_text` | 推送标题 |
| `back_text` | 推送原文摘要 |
| `source_ref.url` | 推送链接 |
| `source` | `interest_explorer` |
| `card_type` | `data`（数据/事实类型）|
| `status` | `later`（待处理）|

**复用优势**：

- "稍后读"列表 = 复用 FlashCard 列表，按 `status='later' AND source='interest_explorer'` 筛选
- 统一的复习入口（FSRS 调度）
- 跨设备同步（已有同步通道）
- 批量操作接口

### 7.4 "不感兴趣"反馈

- 用户标记"不感兴趣" → 本地更新对应标签的 `dislike_score`
- 后续推送时，相似标签的采样概率**降低**
- **不**发送到服务端
- 用户可清空本地权重恢复默认

## 8. 从推送到学习闭环

| 操作 | 触发 | 实现 | 副作用 |
|------|------|------|-------|
| 标记稍后读 | 用户点击 | 生成 `FlashCard`（`status='later'`）| 统一进入 FlashCard 暂存区 |
| 导入阅读模块 | 用户点击 | 调用 file-management 导入 | 标记 `FlashCard.status='processed'` |
| 创建知识点 | 用户点击 | 调用 KG API 创建 `CognitiveNode` | 标记 `FlashCard.status='processed'` |
| 创建项目灵感 | 用户点击 | 调用 0001 项目 API | 标记 `FlashCard.status='processed'` |
| 添加卡片 | 用户点击 | 调用 0002 多源提取接口 | 标记 `FlashCard.status='processed'` |
| 分享到语言房间 | 用户点击 | 调用 0004 房间 API | 标记 `FlashCard.status='processed'` |
| 标记不感兴趣 | 用户点击 | 本地 `dislike_score += 0.1` | 不创建 FlashCard |

## 9. 关键设计决策（12 个）

| # | 决策点 | 方案 |
|---|--------|------|
| 1 | 信息源抓取 | `feedparser` + `httpx` |
| 2 | 推送系统 | 复用秘书 `Proposal` 机制 |
| 3 | LLM 使用 | **完全不使用**（与设计原则一致）|
| 4 | 跨学科推送 | 可选（默认关闭）|
| 5 | 任意 URL 抓取 | **不支持**（只支持 RSS/Atom）|
| 6 | 兴趣标签存储 | **独立标签**（轻量解耦）|
| 7 | 内容去重粒度 | **链接级别**（精确去重）|
| 8 | 推送历史保留期 | 可配置（默认 90 天）|
| 9 | 标签层级 | **3 层**（避免复杂度爆炸）|
| 10 | 不感兴趣反馈 | **本地权重**（与"不追踪"一致）|
| 11 | 推送时段 | 用户配置 + 时区感知 |
| 12 | 推送通知 | 仅站内（与系统边界一致）|

| 联动 | 内容 |
|------|------|
| 知识图谱 | 获取兴趣领域标签；推送"被忽视的相关节点"；创建新知识点 |

| 项目模块 | 推送内容作为项目灵感 |

| 事件流 | 推送生成事件、用户保存/导入事件 |

## 11. 隐私与控制

- 兴趣标签、推送偏好、信息源配置存储在本地
- 信息源请求以用户设备名义发起（用户可配置代理）
- **不**追踪用户对推送内容的点击、阅读时长、后续行为用于个性化推荐
- "不感兴趣"反馈**仅在本地**调整权重
- 用户可清空全部推送历史
- 用户可随时暂停推送

---

## 12. 系统边界

**系统可做**：

- 根据用户设定的标签和启用的信息源检索内容
- 按用户设定的频率和比例随机推送
- 汇总信息源中的原文摘要和标题
- 根据"不感兴趣"标记在本地调整随机采样权重
- "稍后读"复用 FlashCard 临时状态

**系统不做**：

- 对推送内容做自动摘要、提炼、评价
- 基于用户行为数据做个性化推荐
- 追踪用户的点击和阅读行为用于优化推荐
- 过滤"低质量"内容
- 主动推荐用户兴趣领域之外的热点（除非开启跨学科推送）
- 调用 LLM 生成内容

## 13. 3 个压力测试场景

### 场景 A：基础推送

用户设置"每日推送"（3 对象 + 2 方法 + 1 热点）。

**压力测试点**：

1. 每日定时通过 `Proposal` 推送
2. 内容完全来自 RSS/Atom 原文
3. 时区感知
4. 链接级别去重

### 场景 B：学习闭环

用户从推送内容分别执行 5 个操作：稍后读 / 导入阅读 / 创建知识点 / 创建项目 / 添加卡片 / 分享到语言房间。

**压力测试点**：

1. 5 个目标模块的导入触发
2. 跨模块数据流
3. FlashCard 临时状态的生命周期

### 场景 C：本地权重

用户对"自然语言处理"标签标记 6 次"不感兴趣"。

**压力测试点**：

1. 6 次反馈后采样概率下降 60%
2. **不**发送到服务端
3. 用户清空本地权重后恢复默认

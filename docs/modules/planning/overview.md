# Planning（信息整合视图与手动编排工作台）

> 后端调度引擎的**前端用户工作台**：不重建后端逻辑，专注"汇聚 + 编排 + 追踪"。

**ADR**：[`docs/adr/0006-planning-module.md`](../../adr/0006-planning-module.md)

---

## 1. 模块定位

Planning 是整个学习系统的**信息整合视图与手动编排工作台**。汇聚来自各模块的待办与状态信息，由用户自主决定学什么、何时学、学多久。

**解决**：用户在多个模块间切换时，如何统一查看待办项、跨模块编排计划、追踪执行。

**不解决**：具体的调度算法（由 `AdaptivePlanGenerator` 负责）；复习提醒（由 `review_reminder` 负责）；疲劳管理（由 `fatigue_manager` 负责）；每日简报（由 `daily_brief` 负责）。

---

## 2. 核心定位：消费者 + 编排入口

**关键决策**：Planning 是**后端调度引擎的"前端用户工作台"**。**不**重建后端逻辑。

```
现有系统（后端调度引擎）              Planning（前端用户工作台）
─────────────────────────              ──────────────────────
AdaptivePlanGenerator            →    提供"建议池"展示
review_reminder（秘书）            →    提供"待复习"列表
fatigue_manager（秘书）           →    提供疲劳信号
daily_brief（秘书）               →    提供日总结数据
habit_formation                  →    提供习惯等级
                                
                              ←    用户拖拽编排
                              ←    用户手动调整
                              ←    执行追踪
                              ←    偏差记录
                              ←    周期回顾
                              ←    目标管理
```

**核心原则**：

- Planning **不**有自己的调度逻辑
- Planning **只**做"展示 + 编排 + 追踪"
- 调度由后端引擎负责

---

## 3. 复用 vs 新建

### 3.1 复用（消费后端能力）

| 复用项 | 来源 |
|--------|------|
| 自适应推荐 | `AdaptivePlanGenerator.generate()` |
| 复习提醒 | 秘书 `review_reminder` |
| 疲劳信号 | 秘书 `fatigue_manager` |
| 每日简报 | 秘书 `daily_brief` |
| 习惯等级 | `habit_formation` |
| 目标日历 | `learning_profile` |
| 心情压力规则 | 0005 MoodStress |
| 题目级调度 | `ZPDScheduler`（**不涉及**，任务级 vs 题目级）|

### 3.2 新建（前端工作台）

- 拖拽式时间轴（日/周/知识视图）
- 自定义视图方案
- 目标管理与周期回顾
- 执行追踪与偏差记录
- 习惯学习建议的展示

## 4. 信息汇聚

### 4.1 从各模块收集的待办与状态

| 来源模块 | 汇聚信息 |
|---------|---------|
| 知识图谱 | 薄弱知识点列表（Belief < 阈值）、近期活跃、待复习节点数 |
| FlashCard | 今日到期卡片数、未来 7 天每日到期预测、按知识点分组 |
| 练习 | 进行中的练习组、推荐复习的练习、待完成错题重做 |
| 项目 | "纳入日程"的任务节点、活跃项目的下一步未完成任务 |
| 阅读 | 进行中的阅读材料、用户设置的回顾提醒 |
| 语言多人 | 用户设定的练习频率目标、上次练习距今时间 |
| MoodStress | 当前压力/能量值、用户配置的调度规则 |

**关键原则**：**不**做自动优先级排序（用户决定）。

## 5. 规划视图

### 5.1 日视图

- 时间轴布局（30 分钟/60 分钟可调）
- 左侧"待安排池"：所有待办项平铺展示（来源、预估耗时、关联知识点、到期时间）
- 右侧时间轴：用户从待安排池拖拽项目完成手动编排
- 已安排项可拖拽调整时间、延长或缩短
- **未**安排项**不**自动填充

### 5.2 周视图

- 7 天并列展示
- 显示每天已安排项数量和总时长
- 显示本周到期卡片总数、练习组数、项目任务数

### 5.3 知识视图

- 以知识图谱为背景
- 叠加显示各知识点的待办密度（关联的到期卡片数、待完成练习数）
- 用户可基于知识点优先级集中安排
- 选中知识点后显示其下所有待办项，可批量拖入

### 5.4 自定义视图

- 用户可保存当前筛选条件和视图布局为个人视图方案
- 支持多种视图方案切换

## 6. 智能辅助（仅辅助，不决策）

### 6.1 习惯学习

- 系统记录用户行为模式：通常在什么时段安排什么类型任务
- 基于历史模式提供"建议搭配"（"你通常在周二下午安排项目任务"）
- 建议**仅作为选项**展示，用户可选择采纳或忽略

### 6.2 冲突提示

- 任务量明显超过历史承受能力时提醒
- 到期卡片数超过用户通常的单日处理量时提示
- 提示**不阻止**用户继续安排

### 6.3 心情压力规则

- 用户可在 MoodStress 模块设定规则
- Planning 在生成当日视图时（用户点击"应用规则"按钮后），**自动将受影响的待办项标记提示色**
- 规则执行结果完全可见，用户可逐项撤销

## 7. 日程执行与追踪

### 7.1 执行界面

- 当日视图进入执行模式
- 每个任务显示：来源模块、具体内容、预估/已用时间、关联知识点
- 用户手动标记任务开始和完成，或跳过
- 完成任务自动通知对应模块更新状态

### 7.2 偏差记录

- 实际执行与计划的偏差自动记录：超时、跳过、临时插入、提前完成
- 偏差数据用于习惯学习（**不**做评判）

### 7.3 日总结

- 每日学习结束后生成总结
- 计划任务数 vs 完成数、总学习时长、各模块时间分布
- 总结写入事件流

---

## 8. 目标与周期管理

### 8.1 目标设定

- 用户手动设定长期目标（"3 个月内完成某项目"）
- 目标与具体模块关联
- 目标进度由对应模块的实际数据自动更新

### 8.2 周期回顾

- 用户设定回顾周期（每周/每月）
- 到时自动汇总：各模块学习时长分布、知识点掌握度变化、目标完成进度
- 回顾数据以图表呈现
- **复用**秘书 `daily_brief` 周期机制

## 9. 关键设计决策（10 个）

| # | 决策点 | 方案 |
|---|--------|------|
| 1 | 与 AdaptivePlanGenerator | 消费+展示+手动调整 |
| 2 | 与 ZPDScheduler | **不涉及**（任务级 vs 题目级）|
| 3 | 复习提醒 | 消费 `review_reminder` |
| 4 | 疲劳管理 | 消费 `fatigue_manager` |
| 5 | 每日简报 | 消费 `daily_brief` |
| 6 | 目标日历 | 复用现有 |
| 7 | 习惯学习 | 复用 `habit_formation` |
| 8 | 心情压力规则 | 消费 0005 输出 |
| 9 | 自动 vs 手动 | **自适应推荐 + 手动调整** |
| 10 | 周期回顾 | 复用 `daily_brief` 周期机制 |

## 10. 与其他模块联动

| 联动 | 内容 |
|------|------|
| 规划 → FlashCard | 获取到期卡片列表和预测；执行完成后回写复习结果 |
| 规划 → 练习 | 获取待完成练习组；执行完成后回写完成状态 |
| 规划 → 项目 | 获取"纳入日程"的节点；执行完成后回写节点状态 |
| 规划 → 阅读 | 获取阅读回顾提醒（0003 触发）；执行完成后回写阅读进度 |
| 规划 → MoodStress | 获取当前状态值和用户设定的调度规则 |
| 规划 → 对话 | 无直接联动（对话为即时工具）|
| 规划 → 事件流 | 每日总结、周期回顾、目标进度写入事件流 |
| 规划 → 目标日历 | 读取目标日历的固定节点作为参考信息 |

## 11. 系统边界

**系统可做**：

- 汇聚展示各模块的待办项和状态数据
- 根据历史习惯提供可选建议
- 根据用户设定的规则**提示**调整项
- 记录执行偏差和统计数据
- 展示目标进度和周期汇总

**系统不做**：

- **不**自动生成学习计划或填充日程
- **不**自动调整待办项的优先级
- **不**强制执行或锁定已安排的任务
- 根据心情压力数据自动调整计划（仅提示）
- 对用户的执行偏差做评价或催促

## 12. 3 个压力测试场景

### 场景 A：日常使用

用户从 7 个模块看到 30+ 待办项，使用自适应推荐 + 手动编排，完成 10 个任务。

**压力测试点**：

1. 自适应推荐基于 `AdaptivePlanGenerator` 正确显示
2. 用户拖拽修改后，**不**影响后端调度
3. 完成任务触发对应模块的状态更新

### 场景 B：考前冲刺

用户设定目标"2 周内复习 500 张卡片"，每日简报展示进度。

**压力测试点**：

1. 目标管理（手动设定 + 自动更新进度）
2. 周期回顾展示（复用 `daily_brief`）
3. 跨模块联动（卡片 + 项目 + 练习）

### 场景 C：心情压力规则

MoodStress 规则"压力≥7 时推迟高强度项目"。

**压力测试点**：

1. Planning 消费 0005 的 `MoodStressRuleTriggered` 事件
2. **只标记**，**不**自动修改
3. 用户可逐项撤销

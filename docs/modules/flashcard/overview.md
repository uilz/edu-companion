# FlashCard（间隔重复记忆卡）

> 知识层之上的**材料层**：基于知识点设计的复习材料载体。

**ADR**：[`docs/adr/0002-card-module.md`](../../adr/0002-card-module.md)

---

## 1. 模块定位

FlashCard 是基于 `CognitiveNode` 设计的**复习材料**。系统提供 FSRS 调度、来源提取、双向溯源等基础设施，**不**代替用户决定哪些内容该记、**不**自动生成卡片内容、**不**自动评价记忆效果。

**解决**：用户在多个学习场景中如何将零散信息（练习错题、阅读笔记、对话片段、项目成果）转化为可长期复习的材料。

**不解决**：知识点的状态管理（由知识图谱负责）；一次性的测试评估（由练习系统负责）；对话上下文标注（由 ExplainCard 负责）。

---

## 2. 层级定位

| 层级 | 实体 | 归属 |
|------|------|------|
| 知识层 | `CognitiveNode` | 知识图谱模块 |
| **材料层** | **FlashCard** | **本模块** |
| 材料层 | `Question` / `ErrorBookEntry` / `ExplainCard` | 已有各模块 |
| 工作台层 | Project / Reading / LanguageRoom | 各模块 |

**核心原则**：

- 状态归 `CognitiveNode`（`Belief` / `Scheduling`）
- FlashCard **不**维护独立的掌握度
- FlashCard **不**替代知识图谱的"知识点"概念
- 复习时通过事件**小权重贡献**给 Belief

---

## 3. 核心能力

### 3.1 调度算法：FSRS 优化版

- FSRS 体系 + 个人记忆参数拟合（稳定性、难度、遗忘速率）
- 用户可设定目标遗忘率（如 0.85）
- 三档自评：困难 / 良好 / 简单
- 算法透明：每张卡片可查看稳定性/难度/下次复习时间
- 不设每日上限（由规划模块统一调度）
- **不**单独维护调度历史于卡片中，只在 FSRS 计算时使用

### 3.2 卡片创建：多源提取

| 来源 | 提取方式 | `source` 字段 |
|------|---------|--------------|
| 手动创建 | 用户在 FlashCard 模块内创建 | `manual` |
| 练习错题 | 一键生成 | `practice_error` |
| 阅读笔记 | 反思型自动创建 | `reading_note` |
| 对话片段 | 选中文本 → 一键生成 | `conversation` |
| 项目成果 | 节点内容提取 | `project` |
| 语言房间 | 转写中选词生成 | `language_room` |
| 兴趣探索 | 推送内容标记稍后读 | `interest_explorer` |

**所有提取的卡片**：

- 保留来源追溯（`source_ref` 字段）
- 复习时用户可展开查看原始上下文

### 3.3 知识组织

- **不设牌组**（避免多套分类系统）
- 每张卡**至少关联一个 `CognitiveNode`**
- 多标签系统（支持层级）
- 动态筛选器：知识点 + 标签 + 来源 + 熟悉度 + 创建时间 + 到期时间

### 3.4 卡片类型（7 种）

| 类型 | 正面 | 反面 | 特殊功能 |
|------|------|------|---------|
| 基础问答 | 问题/概念名 | 答案/解释 | - |
| 填空 | 带空白的句子 | 填空答案及解释 | 多个空逐一揭晓 |
| 对比 | 概念A vs B + 维度 | 各维度差异说明 | 逐维度展开 |
| 流程 | "写出...步骤" | 有序步骤列表 | 乱序自检 |
| 应用场景 | 场景描述 | 知识点 + 推理过程 | - |
| 错题溯源 | 原题/变形题 | 解法 + 知识点 | 自动关联错题 |
| 反思 | 开放式元认知问题 | 用户自己的回答 | 定期对比回答变化 |

## 4. 复习体验

### 4.1 复习流程

```
展示正面 → 用户思考 → 点"显示答案" → 看到反面 + 关联信息
  → 自评（困难/良好/简单）→ 展开：知识点 / 来源 / 历史
  → 撤销上一次自评（误触纠正）
  → 会话结束：统计 + 写入事件流
```

### 4.2 用户控制权

- 手动暂停/恢复任意卡片（保留所有数据）
- 手动重置（清空调度历史）
- 修改内容时弹出"是否重置调度"（默认不重置）
- 查看完整历史：复习时间、自评、间隔变化
- 手动设定下次复习时间
- 批量操作：批量暂停/加标签/改关联/调整难度

## 5. 关键设计决策（11 个）

| # | 决策点 | 方案 |
|---|--------|------|
| 1 | 模块命名 | **FlashCard**（消除与 `ExplainCard` 命名歧义）|
| 2 | 调度算法 | FSRS 优化版 + 个人参数拟合 |
| 3 | 卡片来源 | 多源提取（7 种来源）|
| 4 | 知识组织 | **不设牌组**，多标签 + 动态筛选 |
| 5 | 卡片类型 | 7 种（保留所有类型）|
| 6 | 复习自评 | 困难/良好/简单 三档 |
| 7 | **自评回写 Belief** | 事件流小权重贡献（0.1），与练习错题等协同 |
| 8 | **错题卡自评** | 触发 `ErrorBookEntry.is_resolved` 更新 |
| 9 | **多知识点绑定** | 主 1.0 + 次 0.3 权重 |
| 10 | 复习事件 | 复用 `DomainEvent` 事件总线 |
| 11 | 命名 | `FlashCard` / `flashcards` / `/api/flashcards/*` |

---

## 6. 5 个关键接口决策（与现有系统）

| 决策 | 方案 | 理由 |
|------|------|------|
| 1. 自评 → `Belief` | 事件流小权重贡献（0.1）| 保持 Belief 多源融合一致性 |
| 2. 错题卡 → 错题本 | 触发 `is_resolved = true` | 用户不维护两套错题状态 |
| 3. 多知识点 | 主 1.0 + 次 0.3 权重 | 精细化追踪 |
| 4. 复习事件 schema | 复用 `DomainEvent` | 不再造平行总线 |
| 5. 命名 | `FlashCard` | 消除与 `ExplainCard` 歧义 |

## 7. 与知识图谱的双向联动

### 7.1 卡片 → 知识点

- 每次复习自评结果更新关联知识点的 Belief
- 逻辑：滑动窗口最近几次表现，"困难"拉低、"简单"拉高、"良好"维持
- 知识点页面：关联卡片数、各熟悉度分布、最近复习热力图

### 7.2 知识点 → 卡片

- 知识点薄弱时（Belief 低于阈值），其关联卡片复习优先级自动提升
- 知识点页面可直接发起"复习该知识点所有卡片"

### 7.3 反思型卡片复用

- **阅读笔记** = 反思型 FlashCard（`source='reading_note'`）
- **自动获得**：FSRS 调度、Belief 回写、纵向对比、跨设备同步

---

## 8. 统计面板

- 卡片总量、各类型数量、各熟悉度分布
- 每日复习量趋势图（过去 30 天）
- 平均自评分布（困难/良好/简单比例变化）
- 预测未来 7 天每天到期的卡片数
- 按知识点分组的掌握情况热力图
- 按标签、来源维度的复习统计

## 9. 模块联动

| 方向 | 内容 |
|------|------|
| 知识图谱 → FlashCard | Belief 阈值触发复习优先级提升 |
| 练习 → FlashCard | 错题一键生成 FlashCard（`source='practice_error'`）|
| 阅读 → FlashCard | 笔记（反思型）自动生成（`source='reading_note'`）|
| 对话 → FlashCard | 选中文本提取（`source='conversation'`）|
| 项目 → FlashCard | 节点内容提取（`source='project'`）|
| 语言房间 → FlashCard | 转写片段提取（`source='language_room'`）|
| 兴趣探索 → FlashCard | 稍后读内容生成（`source='interest_explorer'`）|
| FlashCard → 知识图谱 | 复习自评事件回写 Belief |
| FlashCard → 规划模块 | 提供到期卡片列表和优先级 |
| FlashCard → 秘书 | 复习会话事件进入全局事件流 |

## 10. 系统边界

**系统可做**：

- 调度计算（FSRS）
- 多源提取卡片
- 知识图谱双向联动
- 复习统计面板
- 批量操作

**系统不做**：

- 不自动生成卡片内容
- 不自动创建卡片
- 不强制每日完成所有到期卡
- 不直接更新 Belief（仅事件流小权重贡献）
- 不评判用户掌握度

## 11. 3 个压力测试场景

### 场景 A：短期任务（考前 2 周）—— 多源提取复习卡

用户从 3 个渠道提取复习卡：错题本 10 张、阅读笔记 5 张、对话中提问 3 张。

**压力测试点**：

1. 18 张卡片的统一复习入口（FSRS 调度）
2. 不同来源的卡在统计面板的区分
3. 跨来源的相关知识点复习

### 场景 B：长期项目（3 个月）—— 语言学习中项目模块联动

用户学习一门外语，项目中包含 200+ 复习卡。

**压力测试点**：

1. 200+ 卡片的复习进度可视化
2. 复习事件进入项目事件流
3. 跨项目卡片复用
4. 过期卡片的归档处理

### 场景 C：跨模块联动 —— 错题卡与错题本的双向同步

用户做练习产生 5 道错题，错题一键生成 5 张卡（`source='practice_error'`）。

**压力测试点**：

1. 复习错题卡 → `ErrorBookEntry.is_resolved` 同步
2. 错题卡与错题本记录一一对应
3. 用户在错题本标记已解决 → 错题卡状态同步
4. 错题卡自评"良好" → 不直接 `is_resolved`（仅事件流）

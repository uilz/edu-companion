# Project（项目式探索构建）

> 用户主导的项目工作台：以树形大纲组织节点，支持节点内版本控制、双向溯源、与各模块双向数据同步。

**ADR**：[`docs/adr/0001-project-based-exploration.md`](../../adr/0001-project-based-exploration.md)

---

## 1. 模块定位

Project 是**完全由用户主导的项目工作台**。系统提供节点类型、版本控制、关联组织、跨模块同步等基础设施，**不主动生成项目内容、不评判节点质量、不强制项目结构**。

**解决**：用户进行跨周/跨月的"主题性研究"时，如何把散落的标注、笔记、参考资料、代码片段组织为可追溯的成果。

**不解决**：单次学习会话内的整理（由阅读模块负责）；碎片化知识点的存储（由知识图谱负责）；间隔重复调度（由 FlashCard 负责）。

---

## 2. 层级定位

| 层级 | 实体 | 归属 |
|------|------|------|
| 知识层 | `CognitiveNode` | 知识图谱模块 |
| 材料层 | `Material` / `MaterialChunk` / `Question` / `ErrorBookEntry` / `ExplainCard` / `FlashCard` | 已有各模块 |
| **工作台层** | **Project / Node** | **本模块** |

**核心原则**：节点状态（如完成度、关联密度）归 `CognitiveNode` 体系，**节点本身是工作台层的容器**，不维护独立的"掌握度"概念。

---

## 3. 视图体系（5 种，Task #89 重构）

Project 详情页支持 5 种视图，用户可在视图切换器自由切换。视图偏好按用户×项目维度持久化。

| 视图 | 路由 | 用途 | 关键能力 |
|------|------|------|----------|
| 手稿 (document) | `?view=document`（默认）| 长文/读书笔记 | 树扁平展示、`@[节点标题]` 引用跳转+高亮、反向引用 Badge、dnd-kit 整体重排 |
| 大纲 (outline) | `?view=outline` | 树形层级 | 折叠展开、子节点、`@[节点标题]` 引用 + 反向引用 Badge、dnd-kit 根节点重排 |
| 看板 (kanban) | `?view=kanban` | 任务跟踪 | 4 列（草稿/进行中/已完成/已归档）、dnd-kit 跨列拖拽改 `status`、列尾 + 添加节点 |
| 知识图谱 (knowledge) | `?view=knowledge` | 节点关系 | 网格卡片 + 邻接可视化（保留原版）|
| 活动流 (activity) | `?view=activity` | 项目活动 | 节点编辑/完成/里程碑/引用事件，按时间倒序 |

**视图偏好存储**：

```python
# user_settings.view.{project_id} = "document" | "outline" | "kanban" | "knowledge" | "activity"
# 详见 docs/adr/0008-project-multiview-architecture.md
```

**URL 兼容**：

- 老路由 `/project/{id}/view/{name}` 保留 redirect → `?view={name}` 形式
- Timeline 路由 `/view/timeline` 重定向到 `?view=activity`（Timeline 已重写为 Activity）

**与节点状态的关系**：

- 看板 4 列 = `project_nodes.status` 字段 4 个值
- 跨列拖拽 = PATCH `/api/projects/{id}/nodes/{node_id}/status` API
- 状态变更不影响其他视图的节点展示

## 4. 节点类型（7 种）

| # | 节点类型 | 用途 | 关键字段 |
|---|---------|------|---------|
| 1 | 大纲节点 | 树形层级组织 | `parent_id` / `order` / `child_node_ids` |
| 2 | 文本节点 | 富文本段落 | `content` (JSONB) |
| 3 | 数据表节点 | 结构化对比/列表 | `rows` / `columns` (JSONB) |
| 4 | 对比节点 | 多列并排对比 | `columns` (每列独立富文本) |
| 5 | 代码节点 | 代码片段 | `language` / `code` / `explanation` |
| 6 | 附件节点 | 文件引用 | `material_id` / `chunk_id_range` |
| 7 | 聚合节点 | 成果板（拖拽片段）| `fragments` (引用的源节点 + offset) |

**所有节点共享字段**：

- `id` / `user_id` / `project_id` / `parent_id`
- `type` (1-7)
- `title` / `description` / `tags` / `order`
- `created_at` / `updated_at` / `version` (当前版本号)
- `linked_node_ids` (关联的 `CognitiveNode`)

## 5. 节点版本控制（横切能力）

**关键决策**：版本控制 = **所有节点自动拥有的横切能力**，不是节点类型。

| 能力 | 说明 |
|------|------|
| 自动记录 | 每次修改自动入栈 |
| 字段级粒度 | 标题/描述/正文各自独立版本 |
| 两版本 diff | 支持任意两个历史版本对比 |
| 单字段回滚 | 任一字段可单独回滚 |
| 回滚入栈 | 回滚本身产生新版本，保留回滚点 |
| 透明度 | 用户随时查看修改历史和 diff |

**项目级快照**（独立机制）：

- 用户标记里程碑时，记录**项目级**整体状态（节点数、关联数、完成率）
- 用于跨阶段对比
- 不替代节点级版本控制

## 6. 节点间关系

### 5.1 引用机制（`@节点`）

- 在节点内容中输入 `@节点名` 触发引用
- **支持节点内和跨项目引用**：
  - 同项目：`@项目A/第一章/1.2`
  - 跨项目：`@项目B/笔记/对比表`
- 引用时显示节点名（不显示 ID），更新后自动同步
- 引用过期（目标节点删除/移动）时显示**橙色标识**，用户可点击修复

### 5.2 跨项目节点复制

- **链接复制**（默认）：复制一个引用，源节点修改会同步
- **深度复制**（可选）：复制完整内容，独立修改
- 系统自动检测循环引用（项目A 引用项目B，项目B 引用项目A → 警告）

### 5.3 节点归档

- 与"删除"区分
- 归档节点不显示在主视图，可在"已归档"列表查看
- 归档节点的引用保持有效（节点仍在数据库中）
- 用户可恢复归档

## 7. 关联组织

### 6.1 单项目规模管理

- 支持 200+ 节点的项目
- 大纲视图：折叠/展开/搜索/批量操作
- 关联分组：标签/分组/批量移除

### 6.2 关联类型

| 类型 | 关系 | 示例 |
|------|------|------|
| `linked_node` | 关联 `CognitiveNode` | 数学题关联"导数"知识点 |
| `linked_material` | 关联 `Material` | 节点引用某本书的章节 |
| `linked_card` | 关联 `FlashCard` | 节点引用复习卡 |
| `linked_node_in_project` | 跨项目节点引用 | 引用其他项目的节点 |

## 8. 双向溯源（5 种输出物的溯源信息）

| 输出物 | 溯源字段 |
|--------|---------|
| 提取为 `FlashCard` | `source_ref.project_id` / `node_id` / `chunk_id_range` |
| 发布为知识图谱个人注释 | `source_ref.project_id` / `node_id` / `comment_id` |
| 拖入成果板（聚合节点）| `source_ref.project_id` / `node_id` / `offset` / `length` |
| 关联到 `Material` | `source_ref.project_id` / `node_id` / `material_id` |
| 纳入规划模块日程 | `source_ref.project_id` / `node_id` / `plan_item_id` |

**反向溯源**：用户在任何溯源目标处点击，可一键跳转回项目对应节点。

## 10. 关键设计决策（10 个）

| # | 决策点 | 方案 |
|---|--------|------|
| 1 | 节点类型 | 7 种性质相同（都是承载内容形态）|
| 2 | 版本控制 | **横切能力**（所有节点自动拥有）|
| 3 | 大纲结构 | 树形无限层级 |
| 4 | 节点间引用 | `@节点` 语法，支持跨项目 |
| 5 | 跨项目复制 | 链接复制（默认）/ 深度复制 |
| 6 | 节点规模 | 200+ 节点的折叠/搜索/批量 |
| 7 | 关联分组 | 标签/分组/批量移除 |
| 8 | 双向溯源 | 5 种输出物的反向跳转 |
| 9 | 跨模块输出 | 8 个模块联动 |
| 10 | 模板系统 | 系统预置 + 个人模板 + 模板版本管理 |

## 15. 系统边界

**系统可做**：

- 提供 7 种节点类型、版本控制、引用、归档
- 提供大纲/时间线/知识关联三种视图
- 跨模块输出（FlashCard/知识图谱/阅读/练习/规划/事件流/对话）
- 项目模板与版本管理
- 全文检索

**系统不做**：

- 不主动生成项目内容
- 不评判节点质量
- 不强制项目结构（用户完全主导）
- 不自动创建子项目
- 不基于用户行为做"项目建议"

## 16. 3 个压力测试场景

### 场景 A：短期任务（1-2 周）——「一题多解」

用户对一道经典数学题做 3 种解法的对比分析。

**节点使用**：

- 对比节点（3 列：解法 A/B/C，每列独立富文本 + 公式）
- 数据表节点（"解法效率对比"：耗时、计算量、适用条件）
- 文本节点（个人心得）

**压力测试点**：

1. 对比节点列内能否插入公式块（LaTeX）？
2. 数据表节点能否引用对比节点的列数据（避免重复输入）？
3. 成果板能否把对比节点的 3 列结论分别作为 3 个片段拖入？
4. 数据表节点能否"反查"被对比节点引用？

### 场景 B：长期项目（3-6 个月）——「Python 系统学习」

用户从基础语法学到实战项目，分阶段推进。

**节点使用**：

- 一级大纲：基础 / 进阶 / 实战
- 二级大纲：每个阶段的子模块
- 代码节点：每个子模块下挂关键代码段
- 附件节点：截图、报错信息
- 文本节点：踩坑日志

**压力测试点**：

1. 节点数膨胀（200+ 节点）下的折叠/搜索性能
2. 代码节点 5 次迭代后的版本对比与回滚
3. 跨项目节点复用（Python 基础学习完后，AI 部分的代码节点能否整组复制到新项目？）
4. 关联练习（学习完一章后关联练习题组，节点能否"显示完成进度"？）
5. 节点归档（完成的项目节点如何处理？）

### 场景 C：跨模块联动 ——「苏东坡主题研究」

用户通读 3 本苏东坡相关书籍，结合知识图谱做"个人化解读"。

**节点使用**：

- 聚合节点：最终文章大纲（从各节点拖入片段）
- 文本节点：每本书的要点摘录
- 对比节点：3 本书对同一事件的描述对比
- 附件节点：年表、地图

**压力测试点**：

1. 关联规模管理（一本书可能 20+ 节点关联，需要标签/分组/批量操作）
2. 双向溯源（在知识图谱里看到"苏东坡视角注释"后，能否一键跳转回项目对应节点？）
3. 聚合节点的来源追踪（成果板拖入的片段，能否反向定位"来自哪个节点的哪个位置"？）
4. 跨模块进度回写（练习模块完成度回流到项目节点显示）
5. 对话模块上下文注入（用户手动选择项目节点作为对话上下文）

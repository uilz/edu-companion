## 新模块功能设计讨论要求

当进行新模块的功能设计讨论时，遵循以下流程：

1. **明确模块定位与边界**
   - 先定义模块要解决什么问题，不解决什么。
   - 明确系统角色：哪些由系统做，哪些由用户做。
   - 明确与其他模块的依赖关系和数据流向。

2. **举例验证**
   - 用 2-3 个具体使用场景检验当前设计是否覆盖真实需求。
   - 场景应覆盖不同类型。
   - 根据场景发现设计盲区并及时修正。

3. **方案讨论与比较**
   - 对关键设计决策提供多个可选方案。
   - 比较各方案在扩展性、复杂度、用户体验、长期维护上的差异。
   - 优先推荐成熟、可长期维护的方案，明确指出各方案的适用场景和取舍。

4. **扩展性与自定义性分析**
   - 评估模块未来可能的扩展方向。
   - 明确哪些部分应对用户开放自定义，自定义的粒度和边界。

5. **利用现有系统能力**
   - 检查模块可复用的系统已有能力，参考 `/docs/architecture/overview.md`。
   - 避免重复造轮子，定义清晰的接口和数据归属。
   - 新增模块不应破坏已有模块的数据完整性。

6. **文档输出**
   - 讨论过程以设计文档形式实时记录在 `/docs/adr/` 中，文件命名：`模块英文名.md`。
   - 模块设计完成后，最终架构文档输出到 `/docs/modules/模块英文目录/`，文件命名同上。

7. **代码实现**
   - 实现模块功能时遵守开发规范。参考 `/docs/agents/domain.md`。

## 一、讨论背景与初衷回溯（锚点）

苹果果的起点是「个人知识体系构建助手——自主学习的全流程助手工具」。

本轮讨论未改变这一初衷，而是在 AGI 加速演进、Agent 井喷的 2026 年背景下，重新回答三个根本问题：

1. **苹果果是什么？**（与操作系统、Agent、平台的关系）
2. **苹果果做什么？**（哪些功能必须自研，哪些交给生态，创造/节奏/复盘如何落地）
3. **苹果果往哪去？**（如何在 AGI 时代保持不可替代性）


## 二、核心定位：从“工具”到“认知镜像”

| 维度 | 定位 | 详细说明 |
|:-----|:-----|:---------|
| **本质** | 个人认知的“镜像层”与“翻译器” | 不生产通用知识，只记录、映射、呈现你对每个知识的**反应轨迹**（卡顿、顿悟、跳跃、犹豫） |
| **对用户** | 最了解你学习轨迹的“沉默的陪伴者” | 不是老师（不教），不是教练（不催），而是“另一个你”——它只呈现你自己都忽略的行为模式 |
| **对外部（AGI/Agent）** | 个人认知的 **“USB-C 接口”** | 外部 Agent 可以读取你的认知上下文，也可以写入执行结果。但**写入必须经过你的确认**，数据主权永远在你手中 |
| **对生态** | 不竞争算力、不竞争通用智能 | 竞争“对个体认知变化的**敏感度**”——即在毫秒级行为序列中捕捉认知状态变化的能力 |

**一句话定义**：当所有 AGI 都在给你答案时，苹果果是唯一记得 **“你当初是怎么提出这个问题的，以及在寻找答案的过程中，你变成了谁”** 。

| **是否自研项目工具** | 不自研，做 Notion 的大脑 | 创造模式需要闭环体验 | **不自研项目执行界面，但记录项目对认知的扰动** | 项目执行是 Agent/Notion 的领地，**认知变化**是苹果果的领地 |
| **监督学习是否为主** | 保留对错反馈，满足考试需求 | 教育最大的敌人是“确定性” | **降级为辅助，核心反馈转为“信息增益”** | 考试是用户的现实需求，但苹果果的信仰是“理解的深度” |
| **首页形态** | 空星云，彻底无监督 | 用户会恐慌并关掉 App | **保留“今日引力种子”（最低可行起点）** | 自主学习者也需要“鞋柜”，减少启动时的决策内耗 |

| **创造模式** | 即 Agent 执行器 | Agent 会与苹果果的心智模型冲突 | **苹果果只记录创造过程的认知变化，不调度 Agent** | Agent 是手，苹果果是镜子 |
| **AGI 时代定位** | 退居幕后做“认知防火墙” | 这背离了“陪伴”的初衷 | **站在用户面前，做“站在你这边”的翻译官** | AGI 是公共大脑，苹果果是个人角质层 |

## 五、核心功能的详细技术蓝图

以下是本轮新增/细化讨论的核心功能的具体实现路径。

### 1. 信息增益反馈（P0-核心反馈机制）

- **计算逻辑**（替代简单对错）：
  - 对于每道题/知识点，系统维护一个**掌握概率分布**（基于 CognitiveNode 中的 Beta 信念）。
  - 用户提交答案后，系统计算**先验熵（H_before）**和**后验熵（H_after）**。
  - `信息增益值 = H_before - H_after`。
- **UI 反馈**（让用户感知到）：
  - 正确时：不显示“正确”，显示 “**✅ 洞察确认！你对此的认知不确定性降低了 X%**”。
  - 错误时：不显示“错误”，显示 “**🔍 意外信号！这次挫败为你带来了 Y 单位的信息量，边界正在外推**”。
- **状态回写**：该增益值作为 Reward 信号写入事件流，直接影响后续 FSRS 调度中的**难度系数（Difficulty）**调整。

### 2. 创造模式认知记录（即“造书/造项目”，苹果果的职责）

- **苹果果不做**：写书编辑器、项目甘特图、文件管理树、调用外部工具。
- **苹果果做**：在用户（或用户委托的 Agent）进行创造时，后台实时记录以下三类数据：
  - **节点引用热力图**：创造过程中调用了哪些现有的 CognitiveNode。
  - **语义扭曲度**：创造产物（如文章草稿）中的向量与原始节点的向量夹角，大于阈值则标记为“**新理解/新解释**”。
  - **跨域连接数**：创造了多少条跨越原 Partition 或 Domain 的边。
- **交付界面**：创造告一段落后，系统弹出简报：“这次创造巩固了 A、B 节点，模糊了 C 节点，创造了 D、E 两条新跨域路径。”

### 3. 学习节奏（相互适应，非托管控制）

- **双向建模参数**：
  - **用户维度**：认知负荷、疲劳指数、最近错误聚集度。
  - **系统维度**：推送内容的难度（检索 FSRS 调节过的记忆稳定性参数）、推送密度。
  - **信任积分（Trust Score）**：初始 50。用户接受推荐（点击/完成）则 +1，用户无视推荐则 -0.5，用户手动反馈“这推荐很烂”则 -5。积分决定次日推送的**胆量**（积分高则多推跳跃性连接，积分低则只推最保守的复习）。
- **界面变化**：用户看不到“进度条”，但能看到 **“今日节奏建议”**——用自然语言描述：“你现在的状态适合攻克一个新领域的前半段（预计 25 分钟）”。

### 4. 元学习周报（复盘）

- **输入**：过去 7 天的事件流（停留时长、跳转路径、修改次数）。
- **特征提取**：计算“死磕指数”（单节点停留 >5 分钟的频率）、“花蝴蝶指数”（每小时切换节点数）、“黄金时间段”（效率最高的 2 小时）。
- **输出格式**：纯自然语言，禁止图表堆砌。
  - 示例：“本周你在下午 3-5 点效率最高，面对陌生公式你倾向于硬啃而非跳跃，这在微积分上有效，但在编程上导致了 3 次挫败。建议下周编程尝试‘阅读官方示例优先’策略。”
- **用户行动点**：末尾附一个“**一键采纳此策略**”按钮，点击后系统调整下周的推荐权重。

### 5. FSRS 排期在苹果果中的特殊应用（修正点）

> 取代老旧的 SM-2，FSRS（Free Spaced Repetition Schedule）基于 **D（难度）、S（稳定性）、R（记忆留存率）** 三参数建模，比 SM-2 更精准。

- **拿来部分**：使用开源的 FSRS 核心算法（如 `py-fsrs`），计算每次复习后的记忆稳定性变化。
- **苹果果自研部分**：
  - **参数注入**：将 CognitiveNode 中的**认知负荷值**和**情绪标签**作为扰动因子注入 FSRS 的难度系数（D）中。高负荷或负面情绪时，系统自动**放大难度系数**，降低排期紧迫度，避免挫败。
  - **多模态输入修正**：如果用户是通过“讲解视频”而非“文本阅读”学习的，系统降低 D 值增量（视频通常更直观）。


## 六、AGI 时代的最终定位：不退缩，不贪大（细化版）

- **不竞争“智慧”**：通用推理、知识广度交给 AGI（OpenAI/DeepSeek/Google）和专用 Agent。
- **竞争“记忆”和“身份”**：你的认知图谱是独一无二的，苹果果负责守护它。
- **对外关系定位**：苹果果是 **“个人认知的 USB-C 接口”**。
  - **读（Read）**：授权外部 Agent 读取当前上下文（最近的困惑节点、薄弱概念）。
  - **写（Write）**：外部 Agent 的产出结果必须通过苹果果的 **“认知沉积层”** 才能写入图谱。
  - **审计（Audit）**：所有读写操作留痕，用户可随时回滚到任意时间点的“认知快照”。
- **对内表现**：始终站在用户面前。当所有 AGI 给你答案时，苹果果问：“**这跟你的问题有什么关系？这个答案改变了你原有的哪一块拼图？**”


## 七、数据结构演进（V3.1 新增）

为了支撑上述蓝图，在现有的 `CognitiveNode` 和 `Event` 基础上，新增以下逻辑实体（不扩表，通过 `Node.metadata` 和 `Event.type` 实现）：

| 实体概念 | 存储形式 | 说明 |
|:---------|:---------|:-----|
| **认知快照（Snapshot）** | `Event(type='snapshot')` | 每晚自动生成的全量节点状态备份，用于回滚和长期对比 |
| **外部锚点（Anchor）** | `Node.metadata['anchors']` | 存放 Notion Page ID、邮件 Message-ID、B站 BV 号，用于上下文注入 |
| **创造轨迹（Trace）** | 新增 `creation_traces` 表（轻量） | 仅记录“开始创造”和“结束创造”时间戳 + 关联节点 ID 列表，不存内容 |
| **信任积分日志** | `Event(type='trust_adjustment')` | 记录每次积分变动的理由（如“接受推荐 +1”、“无视推荐 -0.5”） |

## 九、明确放弃（永远不做清单）

- 自研项目管理系统的 UI（任务看板、甘特图、文件树）
- 自研 Agent 调度器（不帮用户调用外部工具、不帮用户写邮件）
- 强制无监督首页（彻底空星云，无任何起点）
- 毫秒级实时元学习干预（算力成本与延迟不可接受）
- 允许用户自定义数据模型（破坏 `CognitiveNode` 的刚性统一性）
- 任何形式的“学习进度条（完成度 %）”
- 所有社区、社交、协作、多人互动功能（Fork/Merge、公开节点、他人图谱、协作学习等）


## 十、仍待吵的开放性问题（留给后续讨论）

| 序号 | 问题 | 我的当前倾向 | 反方可能观点 |
|:-----|:-----|:------------|:------------|

> **我们不造轮子，不抢 Agent 的活，不跟大厂比算力——我们只做一件事：让无限的外部世界，翻译成有限的、属于你的内部成长。**

## 十二、2026-07-09 设计讨论纪要（已确认决策）

> 以下决策由本轮 grill-me 讨论达成，用于指导后续架构与代码实现。

### 1. 外部 Agent 写入边界

- 苹果果对外部 Agent 的写入采用**守门人策略**：对无法验证或冲突的内容**直接拒绝写入**，需用户人工确认后方可落盘。
- 苹果果不判断内容正确性，但负责数据格式校验、节点归属冲突提示和写入审计。

### 2. 反馈机制落地方式

- **分层展示**：默认向用户展示信息增益文案（"不确定性降低了 X%"）。
- 保留可切换的**考试模式**，在该模式下显示传统对错与分数，满足备考场景的现实需求。

### 3. 认知模型升级

- 立即将 BKT-lite 升级为**图上的概率动态系统**：
  - 每个节点维护 `Beta(α, β)` 后验，每次响应做贝叶斯更新；
  - 采用**收缩先验**，子节点参数向父 topic/domain 收缩，数据稀疏时借力上层，数据充足时独立；
  - 信号沿认知数据系统内部的边（层级、共现、依赖、组块、用户确认的关系）**有界传播** 1-2 跳，强度随距离衰减，每个节点保留独立证据权重；
  - 加入时间衰减因子，长期未练习时后验方差增大、均值下降。
- 节点级掌握度 = `α / (α + β)`，信息增益由响应前后的 Beta 分布熵变直接计算；信息增益不仅来自练习，也来自秘书系统评估的全量交互信号。
- 题目参数（difficulty / discrimination / guess）使用**独立 schema 字段**，由 AI 出题时初始化，运行时根据单用户答题数据在线校准；题目参数用于调整 Beta 更新的权重和似然函数。
- 事件只记录不可变响应事实（用户、题目、答案、耗时等），不包含模型派生值，以支持未来模型升级时重放重建投影。
- 知识图谱（用户自己画的项目/内容组织）与认知数据系统**独立**：认知数据系统的图结构来自节点层级、练习共现、AI 依赖分析、组块形成和用户确认的认知关系，不直接使用知识图谱的边。

### 4. 调度与记忆稳定性

- 认知中心采用**统一概率状态**：复习间隔由 Beta 后验的不确定性（方差/熵）和遗忘速率共同决定，不再独立维护一套 FSRS 状态。
- FSRS 仍可作为 flashcard 等既有模块的底层算法，但认知中心本身以 Beta 分布的时间衰减表达记忆稳定性。
- 秘书系统对复习节奏的修正（如因情绪/负荷调整难度或推迟复习）通过事件流传递给认知中心，认知中心将其作为调度计算的扰动因子应用。

### 5. 事件系统架构

- 从单一练习事件扩展为**全量事件流**，覆盖练习、对话、创造、浏览、编辑、情绪反馈、推荐接受/拒绝等用户与系统交互。
- **混合处理架构**：用户-facing 的响应（节点掌握度、调度状态）同步更新；图传播参数拟合、秘书洞察、元学习周报、复杂模型训练走异步流处理。
- 边界由**延迟需求（SLA）**动态决定，而非一刀切。
- 事件模型新增 `actor_type` 字段，区分 `user` / `system` / `external_agent`，并区分用户主动事件与苹果果产生的事件。
- 认知快照采用**版本化投影 + 事件索引 + 差量快照**，在可回滚性与存储成本之间取得平衡。

### 6. 秘书系统与认知中心的分层

- **元认知中心**只处理干净的认知数据（Beta 后验、掌握度、调度状态、目标对齐、组块等）。
- **秘书系统**处理脏数据（情绪、行为、信任积分、推荐反馈、创造产物审阅），输出调整建议。
- **事件系统**记录原始行为事实。
- 秘书系统是**独立的事件驱动状态机**：维护自己的状态变量（信任积分、情绪状态、用户策略画像、干预历史），由秘书专属的事件处理器异步更新。
- 秘书对调度和推荐的修正通过**事件流**传递给认知中心，不直接读写认知状态。
- **信任积分**由秘书系统维护，秘书直接对认知中心输出的候选推荐队列进行过滤/重排。

### 7. 创造模式细节

- 触发方式：**用户显式开始/结束创造会话**。
- 语义扭曲度：用节点关联内容（笔记、错题、对话片段等）的平均 embedding 作为节点语义，与创造产物 embedding 比较。
- 存储：事件（creation_started / creation_ended）记录原始事实，`creation_traces` 作为物化投影缓存常用查询，由 ProjectionBuilder 维护。
- 创造结束后触发**秘书系统审阅**：秘书评估节点引用热力图、语义扭曲度、跨域连接，决定是否生成信息增益事件、深度加工任务、新的认知边或自然语言简报。

### 8. 元学习周报

- 周报由**秘书系统**生成，输入为过去 7 天事件流和秘书已处理的特征。

### 9. 首页"引力种子"

- 采用**混合优先级**：综合复习紧迫性（Beta 后验不确定性 + 遗忘）、目标关键路径、情绪/认知负荷、创造上下文，计算"引力分数"后取 Top-K 展示。

### 10. 外部锚点与认知沉积层

- 外部锚点（Notion Page ID、邮件 Message-ID、B站 BV 号等）作为**独立实体**存在，节点与锚点为多对多关系。
- 外部资源更新采用**用户主动触发同步**或**外部 Agent 主动推送**，不做主动轮询。
- 外部 Agent 写入认知图谱前必须经过**认知沉积层**：
  - 格式校验与节点归属冲突检测；
  - 对无法验证或冲突的内容**直接拒绝**，需用户人工确认；
  - 所有写入操作留痕，支持审计和回滚。
- 锚点内容拉取后先进入**秘书系统审阅**，由秘书决定是否需要更新节点语义、生成复习任务或提示用户。
